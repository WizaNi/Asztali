# Verziokezeles

a verziokezelo rendszer (Version Control System) nyilvantartja a projekt valtozasait
nem egy masolatot keszit hanem valtozasi tortenetet

Ennek segitsegevel:

- megallapithato, hogy ki/mikor modostiott valamit
- osszehasonlithato
- visszallithato
- parhuzamos fejlesztesi agak
- tobb fejleszto munkaja osszeillesztheto

---

## Verziokezelo rendszerek tipusai

### Lokalis verziokezeles

A verziok egyetlen szamitogepen talalhatok

Elonye: egyszeru, nem kerul ki a forras
Hatranya: gepihiba ellen nem ved, nincs csapatmunka

### Kozpontositott verziokezeles (pl.: SVN)

A kozponti szerver talralmazza a projekt verzioit, fejlesztok ehez kapcsolodnak

### Elosztott verziokezeles (pl.: Git)

Minden klon rendelkezhet a teljes commit-tortenettel, internet v szerver kapcs nelkul is

``` text
Fejleszto A             Fejeszto B
[teljes repo]           [teljes repo]
```

## Git es a Github nem ugyanaz

**Git:** verziokezelo program, lokalis
**Github:** gitet hasznalo szolgaltatas

``` text
Git     = verziokezeles eszkoze
Github  = online szolgaltatas a Git projektekenk
```

## A git alapfogalmai

### Repository

A **repo**, git altal kezelt projekt
a projekt konyvtaraban letrejovo rejtett `.git` konyvtar tartalmazza - tobbek kozt - a:

- a commitokat
- az agak adatatit
- a konfiguraciot
- a repo tortenetet
A `.git` konyvtar torlese eseten a minkafileok megmaradnak, Git tortenete elveszik

### Working Directory

Azok a fileok, amik a projekt mappaban tartunk

### Staging Area

Egy koztes terulet, a kovetkezo commit mely modositasokat tartalmazza

### Commit

Commit tartalmazza:

- szerzo
- date
- uzenet
- allapotadatok
- egyedi azonosito (hash)

Egyszerusitett folyamat:

``` text
Working Dir
    |
    | git add <file>
    v
Satging area
    |
    | git commit -m "commit message"
    v
Repository
```


## Elso repo letrehozasa

### Projektkonyvtar

``` bash
mkdir git-gyakorlas
cd git-gyakorlas
```

### Git inicializalasa

``` bash
git init
```

Ettol a konyvtar Git repo lesz

``` bash
git status
```

## Elso file

Hozzunk letre egy `README.md` file-t

``` markdown
# Git gyakorlas
 
Ez az elso Git repom
```

``` bash
git status
git log
```

A file meg untracked vagyis a git latja de nem koveti
Nincsenek commitok a git-ben

### Staging

``` bash
git add README.md
```

### Elso commit

``` bash
git commit -m "Projekt inicializalasa"
```

`-m` utan rovid de beszedes leiras

### Tortenet

``` bash
git log
```

Egyszerusitett megjelenites:

``` bash
git log --oneline
```

## Mit jelent a jo commit?

> Egy logikailag osszetartozo valtoztatast tarlamazzon
>
> Kevesbe jo:
>> valtozasok
>> kesz
>
> Jobb:
>> README hozzadase
>> Bejelentkezesi urlap validaciojanak javitasa
>
> A cel hogy kesobb a commit tortenetbol ertheto legyen a fejlesztes menete
